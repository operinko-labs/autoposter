# Live Logs Page — Verification Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Web UI streams the process's own log output (what
`kubectl logs -f` shows) live on a new "Logs" page, verified green in the
container on both suites.

**Architecture (already applied as a draft commit on this branch):**
`src/autoposter/api/logs.py` — `LogBuffer(logging.Handler)`: bounded deque
(1000) of `{ts, level, logger, message}` dicts, per-subscriber asyncio queues
(maxsize 500, drop-on-full), thread-safe `emit` via `call_soon_threadsafe`,
`uvicorn.access` excluded; `GET /api/logs` (snapshot) and
`GET /api/logs/stream` (NDJSON: backlog → live → `{"heartbeat": true}` per
15s idle), both behind `require_session`. Handler attached to the root logger
only in the lifespan's `run_background` branch (detached in `finally`);
`app.state.log_buffer` created unconditionally in `create_app`. Frontend:
`apiFetchNdjson` in `api/client.ts` (bearer header — `EventSource` can't
send one, same constraint as `apiFetchImage`), `pages/Logs.tsx` + `logs.css`
(2000-line cap, level+text filter, follow-ref auto-scroll, 3s auto-reconnect
that clears the list first because the server replays its backlog),
route `/logs`, sidebar entry.

**Status:** the draft was written but never verified — no suite, ruff, tsc,
or build has ever run against it. This plan is that verification, plus the
fixes that fall out and the mutation proofs SDD requires.

## Global Constraints

- `.superpowers/sdd/p4c-verified-facts.md` binds throughout (read it first).
- **Container-only testing, from this worktree (`D:\Sites\autoposter-logs`):**
  - Frontend: `docker compose run --rm web npm test`, then
    `npm run build` the same way. (`web` has no postgres dependency and `run`
    publishes no ports, so the main checkout's stack does not conflict; the
    fresh `frontend_node_modules` volume install makes the first run slow —
    that is normal, do not interrupt it.)
  - Backend: `docker compose -p autoposter run --rm test pytest …` — `-p
    autoposter` joins the main checkout's compose project to reuse its
    running postgres (host port 5433 is already bound by it); the bind mount
    still comes from this worktree, so this branch's code is what runs.
    NEVER two pytest sessions at once (shared DB: deadlocks and
    StaleDataError fake regressions). No other session is running one.
- **Known risk 1 — httpx `ASGITransport` buffers**: it runs the app to
  completion before returning, so an endpoint-level test of the unending
  stream hangs. Run `tests/test_api_logs.py` FIRST, wrapped:
  `docker compose -p autoposter run --rm test timeout 180 pytest tests/test_api_logs.py -q`.
  If the stream tests hang or fail on this, refactor: factor the NDJSON
  generator so tests drive it directly (bounded iteration + `aclose()`),
  keep endpoint-level tests only for what terminates (401s, snapshot).
- **Known risk 2 — jsdom stream harness**: `Logs.test.tsx` builds
  never-closing `ReadableStream` responses; if jsdom/vitest chokes (missing
  APIs, open-handle warnings that fail the run), adapt the harness (e.g. a
  hand-rolled reader stub honouring the abort signal) rather than skipping
  any test — zero skips.
- The structural auth sweep (`tests/test_api_login.py`) walks
  `app.openapi()`: both new endpoints must pass it as-is. Do not weaken the
  sweep; if it fails, fix the endpoints.
- Baselines on this branch's parent (origin/main 64ddf3b): backend **1274
  passed**, frontend **52 passed**. End at/above (backend +~10 from
  `test_api_logs.py`, frontend +4), zero skips.
- Mutation proofs (mutate → red → copy+cmp restore → green, transcripts in

  heartbeat-ignored in the page (break `isLogLine` → test reds); level
