# DC Three-Way Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single DC Universe row in `_UNIVERSE_LISTS` with a new three-collection `content_dc` preset — "DC Universe" (TMDb list 8642250), "DC Extended Universe" (MDBList `fa11en82/dc-extended-universe`) and "In Association With DC" (MDBList `fa11en82/in-association-with-dc`) — probed live before anything is transcribed.

**Architecture:** T1 probes all three lists live through the shipped clients (`TmdbListClient`, `MDBListClient`) with a throwaway script, gating the phase: an inaccessible list STOPS everything at T1 (the failure mode PR #94 exists to prevent). T2 is the catalog change: the DC row leaves `_UNIVERSE_LISTS` (9→8, digest regenerated two-site), a new `_DC_LISTS` table and `content_dc` preset land with their own digest and shape guards, and every provenance comment is rewritten to describe the new state. T3 is the wrap: roadmap row 201 filed and closed, row 202 filed open (the operator-defined-collection UI, a user directive), the PR body, and the full-suite sweep.

**Tech Stack:** Python 3.14 + pytest (compose `test` service), pydantic v2 params models, sha256 drift digests. No frontend changes — the picker is server-driven and renders the new preset with zero TypeScript edits.

**Binding adjudications:** `.superpowers/sdd/p-dcsplit-facts.md` C1–C7. They are settled; nothing in this plan re-litigates them, and neither does any implementer.

**The C5 lifecycle verdict, resolved against shipped code (T3 discloses exactly this):** when the DC row leaves `_UNIVERSE_LISTS`, an operator with `content_universes` enabled and `content_dc` not ticked keeps a "DC Universe" collection in Plex that carries the ownership label and a `managed_collections` row but that no definition builds any more. `engine._sweep` (`src/autoposter/collections/engine.py:786-931`) is the only code that deletes a collection, and that collection becomes one of its candidates (`engine.py:869-912`). Under the default `collections.delete_unconfigured: false` it is **reported every pass and never deleted** — "`'DC Universe'`: …; set collections.delete_unconfigured to delete it" (`engine.py:914-920`). Only under that opt-in is it deleted, and then still through the `max_deletes` cap (`engine.py:922-931`, which refuses the whole sweep past the cap). Ticking `content_dc` re-adopts it: the new preset's first collection carries the same title, both old and new are list (non-smart) collections so the shape-conflict guard (`reconcile.py:222-264`) does not fire, and the next pass replaces its membership with the TMDb list's. So the verdict is: **the default-off delete path — unmanaged-and-reported by default, deleted only on explicit opt-in, seamlessly re-adopted by the new preset.**

```python
"""Throwaway T1 probe for the DC three-way split -- DELETED before T1 ends.

Prints NO key material: both credentials are read from the environment and
travel only where the shipped clients put them (a header for TMDb, a query
parameter MDBList's client already strips from every message and cache key).
Budget-polite: exactly ONE request per MDBList list, per facts C2. The
refusal handlers print only what the clients' own messages carry -- both are
documented key-free -- and any OTHER exception prints its class name alone,
so a transport error embedding a URL cannot leak the MDBList query string.
"""
import asyncio
import json
import os
import sys

import httpx

from autoposter.facts.mdblist import MDBListClient, MDBListLimitReached, MDBListRefused
from autoposter.providers.tmdb_lists import TmdbListClient, TmdbListRefused

TMDB_LIST = 8642250
MDBLISTS = ("fa11en82/dc-extended-universe", "fa11en82/in-association-with-dc")


async def main() -> None:
    out = {}
    async with httpx.AsyncClient(timeout=30) as http:
        token = os.environ["AUTOPOSTER_TMDB_TOKEN"]
        tmdb = TmdbListClient(token, http)
        movies = await tmdb.list_items(TMDB_LIST, media_type="movie")
        shows = await tmdb.list_items(TMDB_LIST, media_type="tv")
        # One raw page-1 read for sample TITLES -- the shipped client
        # deliberately returns bare ids.
        response = await http.get(
            "https://api.themoviedb.org/3/list/%d" % TMDB_LIST,
            headers={
                "Authorization": "Bearer %s" % token,
                "accept": "application/json",
            },
        )
        response.raise_for_status()
        items = response.json().get("items", [])
        out["tmdb:%d" % TMDB_LIST] = {
            "movies": len(movies),
            "shows": len(shows),
            "sample": [
                {
                    "media_type": entry.get("media_type"),
                    "title": entry.get("title") or entry.get("name"),
                }
                for entry in items[:8]
            ],
        }

        mdblist = MDBListClient(os.environ["AUTOPOSTER_MDBLIST_APIKEY"], http)
        for reference in MDBLISTS:
            pairs = await mdblist.list_items(reference)  # ONE request
            kinds: dict = {}
            for mediatype, _entry in pairs:
                kinds[mediatype] = kinds.get(mediatype, 0) + 1
            out["mdblist:%s" % reference] = {
                "total": len(pairs),
                "by_mediatype": kinds,
                "sample": [
                    {"mediatype": mediatype, "title": entry.get("title")}
                    for mediatype, entry in pairs[:8]
                ],
            }
    print(json.dumps(out, indent=2))


try:
    asyncio.run(main())
except (TmdbListRefused, MDBListRefused, MDBListLimitReached) as error:
    # These messages are key-free by the clients' own documented contract.
    print("REFUSED %s: %s" % (type(error).__name__, error))
    sys.exit(1)
except Exception as error:  # noqa: BLE001 -- the leak guard, see docstring
    print("FAILED %s (message withheld -- it could carry a URL)" % type(error).__name__)
    sys.exit(1)
```
