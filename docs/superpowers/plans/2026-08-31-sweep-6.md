## Adjudications Made by This Plan

Decisions the facts file left to plan time, settled here so no executor guesses.

- **`missing` tallies items, not files or fields, in every one of the five result dataclasses — even where that mode's own `failed` bucket counts files (`restore.py`, `revert.py`) or fields (`reset.py`).** `RestoreResult.failed`/`RevertResult.failed` are file-counts (`failed += len(entries)`) and `ResetResult.failed` is a field-count (`failed += len(kinds)`), because a failed *push* touches every planned file/field of the unreachable item. A 404 on `fetch_item` is different: nothing about the item was even examined, so there is exactly one meaningful unit to count — the rating key itself. This also matches `BackupResult.missing`, which counts rows, not files. Consequence: `reset.py`'s and `logo.py` `LogoRevertMode`'s `missing` counter is a plain `+= 1` in both the probe loop and the apply loop, even though `failed`/`cleared` beside it are field- or item-counts computed differently per loop.
- **`missing` sits in `as_response()`'s unconditional base dict, not the status-gated block**, alongside `items`/`skipped`/`fields`/etc. — never beside `pushed`/`failed`/`reset`/`uploaded`/`cleared`, which appear only under a non-refused, non-dry-run status. Rationale: for `reset.py` and `logo.py`'s `LogoRevertMode`, a 404 can occur during the *probe* phase, which runs before the dry-run/refusal branch — so `missing` can be nonzero even on a `"dry run"` or `"refused"` response. Making it unconditional in all five modes keeps one shape rather than a per-mode special case.
- **The dataclass field itself is named `missing` in all five classes** (matching `BackupResult.missing`), inserted immediately before `refused: str | None = None` — matching PR #112's own field ordering (`items, written, skipped, failed, missing, refused`) — so every existing positional constructor call stays valid untouched; only the returns that now know a nonzero count add `missing=<value>` as a keyword.
- **The per-item log message is standardized across all five sites to `"<mode-prefix>: %s no longer in Plex, skipped", rating_key`** — id-only, matching `backup.py`'s hotfix exactly — rather than preserving `logo.py:234-237`'s current `"logo: could not probe Plex item %s (%s)", row.rating_key, type(exc).__name__` shape (id **and** class name). The class name is redundant once the branch is already `except PlexNotFound` specifically, and one shape across all six sites is the row's own point ("the fourth precedent doesn't disagree with the other five once they ship"). This means `tests/test_artwork_logo.py::test_updater_logs_one_line_for_a_stale_rating_key` — which currently asserts the WARNING-level, class-name-bearing message — is rewritten, not left alone; Step-by-step below.
- **`logo.py` `LogoMode`'s probe-loop `missing` local variable is named `missing_from_plex`, not `missing`**, because `run()` already has a local `missing: list[MediaItem]` (the items lacking a clearlogo) at that scope; reusing the name would shadow it. The dataclass field it feeds is still called `missing`, matching every other class.
- **`_walk`'s visited set (settings-clarity Minor 2's secondary note) is FILED, not implemented.** It requires a new parameter, an early-return guard and a set mutation — four lines touching a recursive signature two call sites (`build_field_descriptions` and `_walk` itself) — which this plan reads as more than the "one-liner" the facts condition on. Task 3's PR body names it as a follow-up rather than silently dropping it.
- **The vocab guard is a new, separate scan (`_unsupported_container_fields`), not a change to `_walk`/`_model_of`/`_item_model_of`.** It re-derives, independently, every `BaseModel` type an annotation's type arguments name (recursing through `get_args`) and compares that set against what `_model_of`/`_item_model_of` already extract — so it can detect the exact blind spot those two functions share without changing their behavior (a walk rewrite is explicitly out of scope per facts C1).

def _model_types_reachable(annotation) -> bool:
    """True if this annotation is a shape ``_model_of``/``_item_model_of``
    cover: a model, ``Model | None``, or ``list[Model]`` (each optionally
    wrapped in the other)."""
    return _model_of(annotation) is not None or _item_model_of(annotation) is not None


def _model_types_present(annotation) -> set[type]:
    """Every ``BaseModel`` subclass named anywhere in this annotation's type
    arguments, however deeply wrapped -- a generic scan independent of the two
    helpers above, so it can tell when their vocabulary has missed one."""
    found: set[type] = set()
    if isinstance(annotation, type) and issubclass(annotation, BaseModel):
        found.add(annotation)
        return found
    for arg in get_args(annotation):
        found |= _model_types_present(arg)
    return found


def _unsupported_container_fields() -> list[str]:
    """Every field, across every model class ``config/schema.py`` defines,
    whose annotation names a ``BaseModel`` type in a container shape neither
    ``_model_of`` nor ``_item_model_of`` can reach -- a ``dict[str, Model]`` or
    a ``tuple[Model, ...]``, say. The walk and the guard both find nested
    models through only those two helpers, so a field shaped like this would
    be served silently as nothing, rather than failing loudly."""
    import autoposter.config.schema as schema_module

    offenders = []
    for obj in vars(schema_module).values():
        if not (isinstance(obj, type) and issubclass(obj, BaseModel)):
            continue
        if obj.__module__ != schema_module.__name__:
            continue
        for name, field in obj.model_fields.items():
            if _model_types_reachable(field.annotation):
                continue
            if _model_types_present(field.annotation):
                offenders.append(f"{obj.__name__}.{name}")
    return offenders
